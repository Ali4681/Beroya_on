# تذكرة Flutter — زر «تعطّل السيارة» ونقل الراكب لسائق بديل

موجّهة لمطوّر تطبيق السائق (والعميل للأحداث).
الـBackend جاهز في `Beroya_on`. **لم يُنفَّذ أي شيء في Flutter بعد.**

لوحة التحكم: بعد بلاغ أثناء الرحلة يظهر «إسناد سائق بديل بعد تعطّل السيارة» على `/erp/rides/:id`.

---

## القواعد

1. **لا تُلغَ الرحلة ولا تُصفَّر الأجرة** بمجرد تسجيل العطل.
2. **قبل الوصول للراكب:** النظام يعيد الرحلة إلى البحث عن سائق آخر (لا عمولة مقطع للسائق الأول).
3. **أثناء الرحلة:** الحالة `INTERRUPTED`؛ الدعم ينشئ رحلة بديلة ويُسند سائقاً.  
   - عمولة السائق الأول = من بداية الرحلة → موقع التعطّل.  
   - السائق الثاني = من موقع التعطّل → الوجهة.
4. بعد البلاغ يصبح السائق **OFFLINE** حتى يضغط Online من جديد.
5. لا تخزّن توكنات في `SharedPreferences`.

---

## 1. زر السائق

ظاهر أثناء: `DRIVER_EN_ROUTE` · `ARRIVED` · `IN_PROGRESS`.

التدفق:

1. «تعطّل السيارة»
2. اختيار النوع: محرك / إطار / وقود / حادث / أخرى
3. تأكيد + إرسال الموقع الحالي
4. عرض «تم إبلاغ الدعم» وإغلاق شاشة الرحلة النشطة

### API

`POST /api/v1/go/driver/rides/:rideId/breakdown`  
Header: `Idempotency-Key`

```json
{
  "subtype": "ENGINE",
  "note": "اختياري",
  "lat": 33.51,
  "lng": 36.27
}
```

| subtype | المعنى | نوع القضية على الخادم |
| --- | --- | --- |
| `ENGINE` | محرك | `BREAKDOWN` |
| `TIRE` | إطار | `BREAKDOWN` |
| `FUEL` | وقود | `BREAKDOWN` |
| `ACCIDENT` | حادث | `ACCIDENT` |
| `OTHER` | أخرى | `BREAKDOWN` |

استجابة مختصرة:

```json
{
  "ride_id": "…",
  "subtype": "ENGINE",
  "phase": "in_progress",
  "status": "INTERRUPTED",
  "fare_unchanged": true
}
```

| `phase` | ماذا يحدث |
| --- | --- |
| `before_pickup` | الرحلة `SEARCHING` لسائق آخر |
| `in_progress` | `INTERRUPTED` — انتظر قرار الدعم / البديل |

### Socket

| حدث | لمن | المعنى |
| --- | --- | --- |
| `ride.interrupted` | السائق المبلِّغ | تأكيد خروجك من الرحلة |
| `ride.breakdown_reported` | العميل + الموظفين | بلاغ عطل |
| `breakdown_case.created` / `case.created` | الموظفين | قضية للمراجعة |
| `ride.replacement_created` | العميل | وُجدت رحلة بديلة (بعد فعل الدعم) |

بعد أي انقطاع: `GET /driver/rides/active` (ستكون `null` بعد البلاغ).

---

## 2. واجهة مقترحة (سائق)

```
[ تعطّل السيارة ]

ما نوع العطل؟
○ محرك   ○ إطار   ○ وقود   ○ حادث   ○ أخرى

[ تأكيد البلاغ ]
«سيتم إبلاغ الدعم. لن تُلغى الأجرة تلقائياً.»
```

أثناء `in_progress` بعد الإرسال: «انتظر تواصل الدعم. مستحقك عن المسافة المقطوعة يُحسب عند نقل الراكب لسائق آخر.»

---

## 3. واجهة العميل (حد أدنى)

- `ride.breakdown_reported` + `phase: before_pickup`: «نبحث عن سائق بديل.»
- `phase: in_progress`: «السائق أبلغ عن عطل. فريق Beroya يتابع.»
- `ride.replacement_created`: حدّث الرحلة النشطة / افتح تفاصيل السائق الجديد.

---

## 4. ما يفعله الدعم (مرجع — جاهز في الداشبورد)

على رحلة `IN_PROGRESS` أو `INTERRUPTED`:

1. «إسناد سائق بديل بعد تعطّل السيارة»
2. سبب `BREAKDOWN` / `ACCIDENT`
3. اختيار سائق (اختياري) → يُنشئ البديل ويُسنده فوراً
4. الخادم يثبّت `original_segment_fare` للسائق الأول

---

## 5. معايير القبول

- [ ] الزر يظهر فقط في EN_ROUTE / ARRIVED / IN_PROGRESS.
- [ ] قبل الوصول: بعد البلاغ لا تبقى رحلة نشطة للسائق؛ العميل ينتظر سائقاً جديداً.
- [ ] أثناء الرحلة: `INTERRUPTED` + لا تصفير أجرة في التطبيق.
- [ ] السائق يصبح Offline ويحتاج Online يدوياً.
- [ ] ضغطتان سريعتان: نفس `Idempotency-Key`.
- [ ] لا زر «تصفير الأجرة» أو «إلغاء تلقائي» مرتبط بالبلاغ.
