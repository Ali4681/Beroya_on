# تذكرة Flutter — عدم حضور الراكب عند نقطة الالتقاء

موجّهة لمطوّر تطبيق السائق (وللعميل في أحداث الحالة فقط).
الـBackend جاهز في `Beroya_on`. **لم يُنفَّذ أي شيء في تطبيق Flutter بعد.** ادمج داخل مشروعكم الحالي وبنفس الـarchitecture.

مرجع السياسة: `CANCELLATION_POLICY.md` (و`RideDefaults` في الباك).

---

## القواعد غير القابلة للنقاش

1. **الخادم يقرر** هل يُسمح بتسجيل عدم الحضور. التطبيق يعرض العدّاد ويعطّل الزر؛ لا «تخمين» محلي كافٍ للسماح.
2. **لا رسوم نقدية** على العميل عند عدم الحضور في السياسة الحالية. لا تعرض «غرامة» أو مبلغ تعويض للسائق من التطبيق.
3. **التعويض المالي للسائق** (إن وُجد لاحقاً) يتم من لوحة المكتب وفق سياسة Beroya — **ليس** زراً في تطبيق السائق بعد عدم الحضور.
4. لا تسجّل عدم حضور قبل `ARRIVED` وبمرور **10 دقائق** من `arrived_at` على الخادم.
5. لا تخزّن توكنات أو بيانات مالية في `SharedPreferences`.

## السياسة الفعلية (ما يفعله الباك اليوم)

| الموضوع | القيمة |
| --- | --- |
| شرط الحالة | الرحلة `ARRIVED` و`arrived_at` موجود |
| مدة الانتظار قبل عدم الحضور | **10 دقائق** (`NO_SHOW_AFTER_ARRIVED_SEC = 600`) |
| انتظار مجاني يُحسب في الأجرة | **دقيقتان** بعد الوصول إذا **بدأت** الرحلة (`FREE_WAITING_SEC`) — غير مرتبط بزر عدم الحضور |
| أثر عدم الحضور على العميل | نقاط جواز سفر مخفية (`NO_SHOW`، −15 في الـseed) — **لا تُعرض** للعميل |
| أثر مالي | إطلاق حجز محفظة السائق، استرداد محفظة العميل إن وُجد خصم مسبق، إطلاق خصم الكود |
| تعويض السائق النقدي | **غير تلقائي** — مسار مشرف/مالية منفصل |
| إلغاء السائق قبل الوصول | مسار آخر (`POST .../cancel`) بنقاط + خصم محفظة — **لا تخلطه** مع عدم الحضور |

الفرق المهم للواجهة:

- **قبل الوصول:** يمكن إلغاء السائق (عقوبة عليه) — ليس «عدم حضور».
- **بعد الوصول + 10 دقائق بدون راكب:** عدم حضور عميل — الزر `no-show` فقط.

## 1. المسار على الشاشة

```
في الطريق (DRIVER_EN_ROUTE)
  → السائق يضغط «وصلت» أو يُعلَّم الوصول من الخادم
  → ARRIVED + arrived_at
  → عدّاد انتظار 10:00 → 0:00 (من arrived_at)
  → تواصل: اتصال / محادثة الرحلة
  → عند انتهاء العدّاد: تفعيل «الراكب لم يحضر»
  → تأكيد → POST no-show → نتيجة من الخادم
```

### 1.1 تسجيل الوصول

`POST /api/v1/go/driver/rides/:rideId/arrive`

- قبل الطلب: الحالة يجب أن تسمح بالانتقال إلى `ARRIVED` (عادة `DRIVER_EN_ROUTE`).
- بعد النجاح: احفظ `arrived_at` من الاستجابة (أو أعد `GET /driver/rides/active`).
- حدث العميل: `ride.driver_arrived`.
- لا تعتمد على GPS المحلي وحده لاعتبار الرحلة «وصلت» في منطق عدم الحضور — الاعتماد على حالة الخادم.

### 1.2 التواصل مع الراكب (أثناء الانتظار)

متاح أثناء `ARRIVED` (والحالات النشطة):

| الوسيلة | كيف |
| --- | --- |
| اتصال هاتفي | `customer.user.phone` من `GET /driver/rides/:rideId` أو `/driver/rides/active` → `tel:` |
| محادثة الرحلة | `GET/POST /driver/rides/:rideId/messages` — حدث Socket `ride.message` |

اعرض أزرار اتصال ومحادثة بوضوح طوال فترة الانتظار. لا تشترط إرسال رسالة قبل عدم الحضور (الباك لا يشترط ذلك).

### 1.3 عدّاد الانتظار

- المصدر: `arrived_at` من الخادم (ISO UTC).
- المدة المطلوبة: **600 ثانية**. إن أضاف لاحقاً الباك حقلاً في الإعدادات، استخدمه؛ حتى ذلك الحين ثبّت 600 مع نص سياسة ظاهر.
- أثناء العدّاد: زر عدم الحضور **معطّل** مع نص مثل: «يمكنك تسجيل عدم الحضور بعد 10 دقائق — متبقي 7:12».
- عند الصفر: فعّل الزر.
- إن ضغط مبكراً رغم التعطيل (سباق ساعات): الخادم يرد `ARRIVAL_WAIT_NOT_COMPLETE` مع `details.retry_after_sec` — اعرض المتبقي من الخادم ولا تعتبره فشلاً نهائياً.

### 1.4 تسجيل عدم الحضور

`POST /api/v1/go/driver/rides/:rideId/no-show`  
Header: `Idempotency-Key` (مفتاح واحد لكل محاولة منطقية).

قبل الإرسال:

1. حوار تأكيد: يوضح أن الرحلة ستُغلق كعدم حضور وفق سياسة Beroya، وأن الزبون قد يُحتسب عليه في نظام النقاط الداخلي (بدون ذكر أرقام للسائق إن لم تُرجعها الـAPI).
2. عطّل الزر فوراً واعرض «جارٍ التسجيل…».

بعد النتيجة:

| النتيجة | التصرف |
| --- | --- |
| 200 + `status: NO_SHOW` | أغلق شاشة الرحلة، أعد السائق لوضع التوفر من `GET /driver/availability` |
| `ARRIVAL_WAIT_NOT_COMPLETE` | أعد تفعيل العدّاد من `retry_after_sec` |
| `INVALID_RIDE_TRANSITION` | أعد جلب الرحلة النشطة — ربما بدأت أو أُلغيت أو سُجّل عدم حضور مسبقاً |
| انقطاع بعد الإرسال | `GET /operations/{key}` ثم `GET /driver/rides/active` — لا تعرض فشلاً قبل التحقق |

حدث العميل: `ride.no_show` `{ ride_id }` — بدون كشف نقاط.

## 2. واجهة مقترحة (سائق)

بعد الوصول، ورقة سفلية:

```
وصلت إلى نقطة الالتقاء
الانتظار: 03:42 / 10:00
يمكنك تسجيل عدم الحضور بعد اكتمال 10 دقائق.

[ اتصال ]  [ رسالة ]

[ الراكب لم يحضر ]   ← معطّل حتى انتهاء العدّاد
```

بعد التفعيل:

```
[ الراكب لم يحضر ]
هل تؤكد أن الراكب لم يظهر بعد انتظار 10 دقائق؟
[ تراجع ]  [ تأكيد]
```

نص سياسة مختصر ظاهر مرة واحدة (قابل للطي):

> وفق سياسة Beroya: بعد الوصول يُنتظر الراكب 10 دقائق. تسجيل عدم الحضور يغلق الرحلة. لا تُفرض رسوم نقدية على الراكب من هذا الإجراء في التطبيق.

---

## 3. واجهة العميل (حد أدنى)

- عند `ride.driver_arrived`: «السائق وصل — يرجى التوجه لنقطة الالتقاء».
- عند `ride.no_show`: «أُغلق الطلب لعدم الحضور» + العودة للرئيسية.
- **لا** تعرض نقاط الخصم أو مبالغ تعويض مخترعة.

---

## 4. ما لا تبنيه

- زر «تعويضني» أو مبلغ ثابت للسائق بعد عدم الحضور.
- السماح بعدم الحضور من حالة `DRIVER_EN_ROUTE` أو قبل `arrived_at`.
- طابور offline لتسجيل عدم الحضور أثناء الانقطاع — عطّل الزر أو أعد المحاولة بعد التحقق (انظر `FLUTTER_RADAR_OFFLINE.md`).
- خلط مسار «إلغاء السائق» مع «عدم حضور العميل».

## 5. أحداث Socket ذات صلة

| الحدث | لمن | المعنى |
| --- | --- | --- |
| `ride.driver_arrived` | عميل | السائق سجّل الوصول |
| `ride.no_show` | عميل | أُغلق لعدم الحضور |
| `ride.started` | عميل | الراكب ركب — ألغِ شاشة الانتظار/عدم الحضور عند السائق |
| `ride.customer_cancelled` / `ride.staff_cancelled` | سائق | ألغِ العدّاد |

بعد أي إعادة اتصال Socket: `GET /driver/rides/active`.

---

## 6. أكواد الأخطاء

| code | HTTP | التصرف |
| --- | --- | --- |
| `ARRIVAL_WAIT_NOT_COMPLETE` | 409 | انتظر `retry_after_sec` |
| `INVALID_RIDE_TRANSITION` | 409 | أعد مزامنة حالة الرحلة |
| `RIDE_NOT_FOUND` | 404 | اخرج من الشاشة |
| `IDEMPOTENCY_KEY_REQUIRED` | 400 | خطأ برمجي |

## 7. معايير القبول

- [ ] لا يظهر زر عدم الحضور فعّالاً قبل `ARRIVED`.
- [ ] العدّاد يبدأ من `arrived_at` الخادم لمدة 10 دقائق.
- [ ] ضغط مبكر → `ARRIVAL_WAIT_NOT_COMPLETE` يحدّث المتبقي؛ لا إغلاق رحلة.
- [ ] بعد 10 دقائق + تأكيد: `POST no-show` ينجح والرحلة تختفي من النشطة.
- [ ] اتصال و/أو محادثة متاحان أثناء الانتظار.
- [ ] لا نص غرامة نقدية ولا زر تعويض سائق في هذه الشاشة.
- [ ] انقطاع أثناء التسجيل: لا تكرار مالي؛ التحقق عبر `/operations` أو REST.
- [ ] عميل يستلم `ride.no_show` بدون أرقام نقاط.
